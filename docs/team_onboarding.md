## Getting started
1. Accept the GitHub repository invitation using your own GitHub account.
2. Read README.md, docs/project_proposal.md, docs/user_stories.md and docs/product_backlog.md.
3. Open the GitHub Project board and review the current issues.
4. Set up Python and the project locally by following the README.
5. Discuss the current sprint goal and available capacity with the project owner.
6. Before taking on a task, agree on its scope and update the relevant GitHub issue.
7. Commit your own changes using your own GitHub account.
8. Request review from another project member before merging where practical.
9. Update the issue and board when work moves through To Do, In Progress, Testing and Done.
10. Be prepared to explain any work you contribute and how it integrates with the application.

Team roles and task ownership will be discussed and documented when additional members join and the team agrees on the arrangement.

## Local setup
1. Install Python 3.11 or newer.
2. Clone the repository.
3. Create and activate a virtual environment.
4. Install dependencies with `pip install -r requirements.txt`.
5. Run the automated tests with `python -m pytest -q`.
6. Start the application with `streamlit run app.py`.

The current Sprint 1 application supports comparing two text samples. Later features such as document uploads, local document collection comparison, history and reporting are planned increments, not current functionality.

## Git working rules
- Use a separate feature branch for a substantial task where practical.
- Keep commits small and describe the actual change.
- Do not commit passwords, API keys, private student documents or local database files.
- Do not mark an issue Done until its acceptance criteria are met and the result has been tested.
