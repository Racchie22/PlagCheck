# Team Roles and Responsibilities

## Team
The project is planned for four students:
- Rachit
- Rohit
- Harsh
- Jayant

At the time this document was first prepared, the other members had not yet been added to the private GitHub repository. Their participation and role allocation must be confirmed with them. This document is a proposed allocation, not evidence that invitations have been accepted or work has been completed.

## Proposed responsibility split
| Member | Proposed focus | Example tasks |
|---|---|---|
| Rachit | Coordination and integration | Backlog coordination, application integration, README and sprint tracking |
| Rohit | Similarity engine | Text preprocessing, TF-IDF, cosine similarity and algorithm tests |
| Harsh | User interface and file input | Streamlit screens, input validation and document upload |
| Jayant | Persistence and quality | SQLite history, report generation, test support and CI |

These are starting suggestions. The team should confirm or adjust them together. Every member should understand the overall workflow and review the integrated application.

## Working agreements
- Use each person's own GitHub account for their own work.
- Use clear commit messages describing the actual change.
- Prefer small, reviewable changes.
- Ask for review before merging shared feature branches where practical.
- Communicate blockers during short stand-ups.
- Never claim a task, test, review or contribution that did not happen.
- Keep credentials, API keys and private student data out of the repository.

## Lightweight Scrum roles
The team may rotate the facilitator/Scrum Master responsibility. The Product Owner responsibility is to clarify user needs and prioritise the backlog; for this academic project, the team can collectively perform this responsibility unless the instructor specifies otherwise.
