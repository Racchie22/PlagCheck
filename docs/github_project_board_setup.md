# GitHub Project Board Setup

Create one GitHub Project for PlagCheck and use it to track the issues in this repository.

## Create the board
1. Open https://github.com/Racchie22/PlagCheck
2. Select the **Projects** tab. If it is not visible, open the repository's project menu or create a project from your GitHub profile.
3. Select **New project** and choose a **Board** view.
4. Name it **PlagCheck – Agile Project Board**.
5. Add the repository's existing issues #1–#10 to the project.
6. Configure the status field with these columns:
   - Backlog
   - To Do
   - In Progress
   - Testing
   - Done
7. Keep all unselected future stories in Backlog. Move only the work selected for the current sprint to To Do.
8. Use a practical Work-in-Progress limit of 2 items in In Progress. This is a team working agreement, not an automatic GitHub restriction.

## How to use the board
- Backlog: accepted ideas not yet selected for a sprint.
- To Do: selected for the current sprint but not started.
- In Progress: someone is actively working on it.
- Testing: implementation is ready for review or testing.
- Done: acceptance criteria are met and the Definition of Done is satisfied.

Update the assignee on an issue only after the person has agreed to own it. Add comments when a task is blocked or when acceptance criteria need clarification.

## Sprint planning
At the start of each sprint:
1. Agree on a sprint goal.
2. Check team availability and capacity.
3. Select the highest-priority stories the team can realistically complete.
4. Break stories into smaller tasks if needed.
5. Assign an owner and reviewer.
6. Move selected issues to To Do.

At sprint review, demonstrate working features and update issue status based on evidence. At retrospective, record one thing to continue, one thing to improve and one action for the next sprint.

## Note
A GitHub Project board is separate from repository files. Creating issues does not automatically create a board. The board must be created in the GitHub interface.
