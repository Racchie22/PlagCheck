# GitHub Project Board Setup

The PlagCheck GitHub Project board provides a visual view of the repository's user-story issues.

## Board columns
- Backlog: accepted ideas not yet selected for a sprint.
- To Do: selected for the current sprint but not started.
- In Progress: work actively being implemented.
- Testing: implementation is ready for validation.
- Done: acceptance criteria are met and the Definition of Done is satisfied.

## How to use the board
The board tracks the real status of each issue. A sample arrangement used during setup is only a planning example; it must not be interpreted as evidence that work has started or been completed. Move issues as their actual status changes.

A sprint may contain several related user stories that are implemented as one integrated feature set. The issues remain separate so their acceptance criteria and progress can be tracked, but they do not have to be completed or released one at a time. For Sprint 1, US01, US02, US03 and US10 together form the working text-comparison increment.

Update an assignee only after the person has agreed to own the work. During the initial solo implementation, the repository owner can track the selected sprint work without assigning roles to future collaborators. If additional members join later, ownership and review arrangements can be agreed at that point.

## Sprint planning
At the start of each sprint:
1. Agree on a sprint goal.
2. Check available time and capacity.
3. Select the stories that support the sprint goal.
4. Break the selected stories into practical implementation tasks if useful.
5. Move the selected issues to To Do.
6. Agree how the completed increment will be demonstrated and validated.

At sprint review, demonstrate the integrated working feature and update issue statuses based on evidence. At retrospective, record one thing to continue, one thing to improve and one action for the next sprint.

## Note
A GitHub Project board is separate from repository files. Creating issues does not automatically create a board. The board must be created in the GitHub interface.
